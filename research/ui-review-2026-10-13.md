# Eavesdroppy UI review (2026-10-13)

Phase 1 of the UI pass: research, review, plan. No source file was edited. Everything below is a recommendation for the implementation phase.

## What was reviewed, and how

- **Code state.** HEAD `5d2ad90` ("Typed notes move to a floating window owned by the droplet"). The working tree was clean when this started, so the floating notes window (`NotesPanel.swift`), the call-details shelf widget, the buttons-only menu bar and the removal of the notes-location setting were already in HEAD. If the parallel rewrite changes those files again, re-check the file and view names below against the new code before acting on them.
- **Renders (checked).** `droppykit run -- --shots` on a worktree of HEAD (not the live tree), idle and with `EAVESDROPPY_HARNESS_DEMO=recording`, `call`, `event`, `ending`, `speakers`, `teampicker`, `link`, `olddroplet`, and each settings page via `EAVESDROPPY_HARNESS_PAGE`. Tall shots (`--shot-height 2000`) for solo and paired. All images were looked at. Scratch output: `/private/tmp/claude-501/-Users-fahad-code-eavesdroppy/a96c790b-eebe-46bc-a0f9-2a7feb2e87ae/scratchpad/ui/`.
- **Not seen.** (1) The floating notes window: the harness cannot mount an `NSPanel`, so every note about it is from reading `NotesPanel.swift`, `NotesEditor.swift` and the droplet. (2) The glass/accent buttons: the harness paints `DroppyAccentButtonStyle` in the default selection blue and `DroppyQuietButtonStyle` almost flat. "Record" and the selected library tab look like plain text there, while the red "Stop & save" visibly tints. I treat that as a harness rendering artifact (the host resolves `selectionBlueAuto` from the user's accent), not a defect, but it needs one look in a real Droppy. (3) HUD button clicks, still unverified per `review-2026-10-12.md`.
- **Rules applied.** `AGENTS.md`, `DesignGuidelines.md`, `ShelfWidgets.md`, `LiveActivities.md`, `SettingsPanes.md`, `Icons.md`, `ExpandedSurfaces.md`, and the HUD and menu bar protocol docs in the SDK. Each constraint is cited as (rule: ...) where it shapes a choice. The `impeccable` skill's critique frame (hierarchy, state coverage, copy, consistency) was applied by hand; its web-specific tooling does not apply to a SwiftUI droplet. The `emil-design-eng` skill's motion rules were applied only where DroppyKit allows motion (see "Motion" below).

### What already complies (do not touch)

No card or border around the widget root; `context.contentInsets` used once; `DroppySpacing` and `DroppyRadius` tokens; both widths declared; `setHoldsOpen` around the open panels; the settings panes use `DropletSettingsPage`, rows are the SDK's own, and there is no repeated page header; sentence case is nearly clean; every HUD and live activity carries an accessibility label; the library's `rowBox` tiles are the sanctioned "raised tile inside the widget" use of `notchSurfaceCardFill`. The list below is about what is wrong or weak inside that compliant shell.

### Motion (rule: Droppy owns every motion around host-mounted surfaces)

The widget, live activity, HUD and expanded surface may not carry entrance transitions or custom springs. What is allowed, and where the review uses it: `DroppyTransition.element` on a control, label or status line swapped inside the widget, a card or the library; `DroppyTransition.compactContent` on a glyph swapped in a live-activity wing. No pulsing record dot, no custom easing, no tab-switch animation (tabs are a high-frequency action; the `emil-design-eng` rule is no animation there). The floating notes window is the droplet's own `NSPanel`, so it is outside the host rule; keep it animation-free too (shown from a keyboard shortcut, `animationBehavior = .none`).

## (a) Problems per surface, ranked within each surface

Severity: **High** = visible defect on a MacBook or a lost capability; **Med** = clear usability or consistency loss; **Low** = polish.

### HUD notifications (EavesdroppyDroplet.swift `notify()`, Automation.swift `PromptStrip`/`PromptCard`)

- **H1 (High). A short notice is drawn as a strip whose text runs across the camera housing.** `notify()` uses the strip when the text is 34 characters or fewer and has no detail: glyph at the far left and the text at the far right. In the `olddroplet` and `event` shots the text starts well inside the housing outline the harness draws (for "Notes ready: Weekly sync", "Remove the old Meetings droplet in Settings...", "Could not start recording"). A strip is 340pt wide on a notch, the housing is about 210pt of that, so each wing has roughly 40pt of usable width: room for a glyph or a 5-character value, not a sentence. (rule: HUD strip content sits at the two outer edges, nothing in the middle; the harness draws the housing for this reason.) Fix: every `notify()` call is a card (`isExpanded: true`, title plus optional detail, `expandedContentHeight` from the line count). Keep the strip builder glyph-only. Do the same in `PromptStrip`: it is never mounted while `isExpanded` is true, but it fails the harness check today, so shrink it to the glyph plus at most one short word.
- **H2 (Med). Titles carry the object, the detail carries nothing.** "Notes ready: Weekly sync" and "Processing failed: Weekly sync" put the variable in the headline. Fix: title "Notes ready", detail "Weekly sync" with an "Open" quiet button that calls `openNotes`; failure: title "Couldn't write notes", detail the reason, button "Retry". Buttons in HUD cards are unverified in a real Droppy; keep the shelf's Retry as the fallback.
- **H3 (Med). Raw error text.** `notify("Could not start recording", detail: "\(error)")` and `notify("Output folder not available", detail: "\(error)")` print Swift error descriptions. Fix: map to a sentence ("Droppy can't write to the sessions folder. Check the disk and try again.") and log the raw error, as the code already does.
- **H4 (Med). Severity is not expressed.** Everything is `.normal` priority except the auto-stop countdown. "Recording stopped" (disk full) and "Call audio was silent" are things the user must see during a call. Fix: add a `priority` argument to `notify`; the two warnings and "Recording stopped" use `.high`. Keep info notices `.normal`.
- **H5 (Med). The consent line is one long title.** "Recording — let everyone know they're being recorded." is 52 characters and wraps in the card. Fix: title "Recording started", detail "Tell everyone on the call." Consent reminders at start are a convention (Krisp, Granola, Jamie all do some form; see (c)).
- **H6 (Med). Call-detected prompt is generic and lingers.** Wording today: title "Recording a call?", subtitle "Zoom is using the microphone", 45 s on screen. Granola names the kind ("Meeting detected"), has one "Take Notes" action and adopts the title of a calendar event that is within 15 minutes; MacWhisper's "Meeting Detected" goes away after 10 s. Fix: title "Record this Zoom call?", subtitle "Zoom is using your microphone", duration 20 s, and if CalendarWatch has an event within 15 minutes, use its title and attendees (today `startRecording(title: "\(app) call", attendees: [])` ignores the calendar). Files: `Automation.showCallPrompt`, `CalendarWatch`.
- **H7 (Low). Countdown card.** "Call ended?" with "Stopping in 11 s", "Keep recording" (accent, orange) and "Stop now" (quiet) is good and matches Jamie's cancelable countdown. Only change: add the accessibility value so VoiceOver reads the countdown, and use the same orange on the glyph and the accent button (the glyph is orange, the button brown in the render; fine once the host resolves the accent).

### Shelf widget, solo (EavesdroppyDroplet.swift `EavesdroppyWidget`, `widgetDescriptors`)

- **S1 (High). Idle: 60pt of dead space, and the two utility rows are the whole content.** The solo rectangle is `.fixed(170)`, the content ends near 110. "Import recording..." and "Open meetings folder" fill the list when nothing is pending, so the widget says nothing about the user's meetings. (rule: no unused space; declare the height the content needs; content-adaptive height via `host.shelf.invalidateLayout(for:)` when the model crosses a size threshold.) Fix: header; title field row with Record; then "Recent" with up to 3 rows from `library.meetings` (title, "Today, 2:30 PM", "2 actions"), each opening that meeting; `Import recording...` and `Open meetings folder` move into an overflow menu (a `Menu` styled `DroppyCircleButtonStyle(size: 20)` with an ellipsis glyph) at the header's trailing end beside the library button. Height: compute from state (idle with 0 recents 78, with recents 120, plus 20 per pending or failed row, cap 170) and call `invalidateLayout` only when the row count changes, never per tick. The widget currently lists `recent` folder names (`(path as NSString).lastPathComponent`), which are raw folder names; use the library model instead.
- **S2 (High). The title field has no field affordance and its placeholder never shows.** `titleDraft` defaults to "Meeting", so the plain 13pt text reads as a label and "Meeting title" is never visible. Fix: wrap the `TextField` in a chip with `AdaptiveColors.notchSurfaceCardFill` at `DroppyRadius.ms` (rule: card fill is for a chip inside the widget), start `titleDraft` empty so the placeholder "Meeting title" shows, and keep `startRecording()` falling back to "Meeting" (it already does). Import's custom-title check (`typed != "Meeting"`) then becomes `!typed.isEmpty`.
- **S3 (Med). The audio warning has no action and is easy to miss.** Orange 11pt text "Call audio unavailable: allow Droppy under Screen & System Audio Recording" (74 characters, two lines at 420pt). It is also only visible while the shelf is open, and the shelf closes when the pointer leaves it, which in a call is almost always. Fix: one row, `exclamationmark.triangle.fill` plus "No call audio. Allow Droppy in Screen & System Audio Recording." and a trailing quiet button "Open System Settings". The deep link is the open question: `host.permissions.openSystemSettings(for: .screenCapture)` exists in the SDK but `screen-capture` is not a declared capability (the user sees that list), while `host.workspace.open(URL)` with the Privacy_ScreenCapture settings URL needs no capability but is unverified from inside the host. See decision D8.
- **S4 (Med). State swaps carry no host transition.** Record to Stop, the header glyph (waveform, hourglass, record dot) and the clock appear and disappear instantly. (rule: a control, label or glyph swapped while a card is up takes `DroppyTransition.element`; never a transition of your own.) Fix: `.id(state)` plus `.transition(DroppyTransition.element)` on `primaryButton`, the header glyph and the warning row. Minimum API 1.8.0; the droplet declares 1.18.0.
- **S5 (Med). Discard sits next to Stop, and the confirm label changes the layout.** "Discard" becomes "Confirm discard" for 4 s (a droplet-side timer), which widens the button and moves "Stop & save". Fix, two options. Cheap: give the discard button a fixed width. Better: `DropletConfirmationDialog.present(...)` from the button (the host draws its own glass popup; SettingsPanes.md "Confirming a change"). That deletes `confirmingDiscard`, `confirmingDelete` and `armConfirm`, but raises `kit.minAPI` to 1.19.0 and does not authorize in the harness. See decision D3.
- **S6 (Low). Hierarchy while recording.** Header "Eavesdroppy" 12pt, then the meeting title 13pt medium, then attendees, then buttons. That order is right. The trailing library button (a `books.vertical` glyph) sits next to the clock and reads as clutter at 20pt; once the overflow menu exists (S1) the library entry goes inside it while recording.
- **S7 (Low). Processing rows.** "Processing: Weekly sync..." with an hourglass hides how far along it is. The pipeline already has named stages (`Port/Processor.swift` `mark(...)` logs them). See (c): Jamie shows live steps. Plumb a `stage` string from `Processor` to the `Job` and show "Transcribing", "Identifying speakers", "Writing notes". Wording only until plumbing lands.
- **S8 (Low). Copy.** "Open Settings" in the permission row is the macOS pane: say "Open System Settings". "Failed: Weekly sync" reads as a verdict; "Couldn't process Weekly sync" with the reason line already below is kinder.

### Shelf widget, paired (210pt, `compactBody`)

- **P1 (Med). Idle paired: "Ready" and 100pt of nothing.** The solo height (170) is applied to the row, so a 70pt composition floats. (rule: one height for both compositions; declare the one both fit.) Fix: the height rule from S1 covers it; idle paired is the title (last meeting's title or "Ready"), a Record button, and nothing else.
- **P2 (Low). Button order differs from solo.** Paired shows Stop above Open notes; solo shows Open notes left, Stop right. Pick one order: primary action first in paired (Stop, then Open notes) is right for a narrow slot; keep solo as is but mirror the emphasis (Stop is the only accent).
- **P3 (Low). The clock is a 12pt header value.** In the 210pt slot "One number" is the rule: make the clock the number (13pt medium `.monospacedDigit()`), the title one line beneath, and drop the repeated "Eavesdroppy" label's competing weight by using secondary text.

### Live activity (EavesdroppyDroplet.swift `makeCompactLeading`, `ClockLabel`, `publishActivity`)

- **LA1 (Med). A problem during the call is invisible.** The row is a red ring and a clock, always. With no call audio (the most common failure on this Mac, 60 s grace) nothing in the notch changes. Fix: leading glyph swaps to orange `exclamationmark.triangle.fill` while `warnings` is non-empty, with `DroppyTransition.compactContent`; republish `accessibilityTitle` ("Recording Weekly sync, no call audio"). Keep `priority` and `isInteractive` fixed (rule: publish one stable state; only `accessibilityTitle` ticks).
- **LA2 (Med). The clock has no hours.** `String(format: "%d:%02d", elapsed / 60, elapsed % 60)` shows `75:12` for 1 h 15 m. This is a bug, found by reading `clock` (EavesdroppyDroplet.swift line 655), not in a render. Fix: `h:mm:ss` from one hour. Both wings and the shelf header use the same property. The 70pt wing fits `1:15:12` at 12pt monospaced digits; check it in the live-activity shot.
- **LA3 (Low). Nothing is on the notch after Stop.** Processing takes minutes; the only signal is the shelf row and the final HUD. Option: publish a low-priority state while `pending` is non-empty (leading `ProgressView`-style glyph is not allowed to animate on its own; use a static `sparkles` or `hourglass` glyph, trailing "2" for queued jobs), `nil` the moment `pending` empties. This holds the seat for minutes, so decision D4.
- **LA4 (Low, no change).** Do not add a pulsing dot, a Stop button or an expanded card: rule (the row is compact only, hovering opens the shelf, Stop belongs in the widget, no custom animation).

### Menu bar (EavesdroppyDroplet.swift `MenuBarContent`)

- **M1 (Med). While recording, the menu says nothing about what is recording.** Three buttons: Open notes, Stop & save, Discard. Fix: one 11pt secondary status line above the buttons, "Weekly sync · 12:34" (it observes the droplet already). If you want strictly buttons only, that is decision D1. Note: Jamie puts the elapsed time next to the menu bar icon, but `MenuBarExtraDescriptor` has only `title` (accessibility) and `systemImage`, so the droplet cannot draw text beside the icon.
- **M2 (Med). The buttons shrink-wrap and left-align inside a 280pt popover.** In the render the hit target is a small pill and the rest of the popover is empty. Fix: `.frame(maxWidth: .infinity, alignment: .leading)` on each label so the whole row is the target, and reduce the width to about 220pt. The fixed-size rule is real (Droppy sizes the menu once at mount): keep the same width and height in both states, as today.
- **M3 (Low). The "Discard" arm-and-confirm pattern repeats here.** Same fix as S5.
- **M4 (Low, decision D5). The item is always in the menu bar.** The protocol allows returning `nil` when the droplet has nothing to contribute. An always-present icon is clutter for a droplet whose widget is the front door, but the host only re-reads after its own state broadcasts, and I did not verify that a droplet-driven state change triggers one. Do not change without testing in Droppy.

### Library / expanded surface (LibraryViews.swift, LibraryModel.swift, Library.swift)

- **L1 (High). Typed notes vanish after the meeting.** `MeetingDetail.userNotes` is loaded (`Library.swift` line 236) and shown nowhere: `NotesTab` renders only `d.notes`. The user types notes during the call (that is the Granola proposition the product was scoped on, v1-scope item 8) and then can never read them next to the generated notes. Fix: in `NotesTab`, when `userNotes` is non-empty, a two-option row "Notes | My notes" (selected = `DroppyAccentButtonStyle`, the other `DroppyQuietButtonStyle`, both `.small`); "My notes" renders `MarkdownText(md: d.userNotes)`. Sources conflict on whether Granola itself has a raw/enhanced toggle (see (c)); this fix stands on its own merit.
- **L2 (High). Five stacked controls before the list.** Ask bar, Search, status line, Linear team picker and export-link row all push the list down; in the `link,teampicker` render the three meetings start more than halfway down a 500pt surface. Fix: Search stays at the top; the Ask bar docks at the bottom of the surface (chat-style, with its scope menu), its answer card expands upward; the team picker, export link and status line become one banner slot that overlays the bottom edge (not in the flow), entering with `DroppyTransition.element`. That gives the list the full height and separates "find" from "ask". Alternative: one field for both (Return searches, a visible "Ask" button asks). I prefer the docked bar: one field doing two jobs is the failure mode Granola avoids by keeping "Ask anything" a separate bar. Decision D2.
- **L3 (High-Med). Speaker rows: the best action is the most hidden, and every row has two buttons.** Each row has "This is..." and "Rename", including the user's own "Me" row. The voice suggestion ("Is this Priya Nair?" with "Yes, it is") is a third line under the stats. Fix: if a suggestion exists it is the row's headline action ("Priya Nair?" with `DroppyAccentButtonStyle` "Yes" and quiet "Not them"); no "This is..." on `kind == "me"`; one "Name" menu otherwise (people first, "New person...", "This meeting only" last, which absorbs the three-way scope menu today shown after Rename); and a play button per row that seeks to that speaker's first turn (`model.seek(turns.first { $0.speakerID == s.id }.start)`; the transcript already seeks). Jamie's speaker flow is "listen to a short clip, then name it", the strongest documented pattern (see (c)); today the user has to leave the Speakers tab, find a turn, and click it.
- **L4 (Med). The list is a flat run of absolute dates.** "Mon 12 Oct, 11:30 PM · 1h 05m". `Fmt.when` hardcodes `"EEE d MMM, h:mm a"`, which also ignores a 24-hour locale. Fix: group headers "Today", "Yesterday", "This week", "Earlier" (11pt tertiary, sentence case), rows "Today, 11:30 PM" via locale-aware `Date.FormatStyle`; "2 open" becomes "2 actions"; a row with no duration ("Empty import") shows "No speech detected" in tertiary instead of "—". Grouping is my judgement; no vendor documents list grouping (see (c)).
- **L5 (Med). Every status line is orange.** `LibrarySurface` draws `model.status` in `Color.orange`, and `flash()` is also used for success ("Imported 3, skipped 0, failed 0"). Orange means a problem. Fix: `flash(_:isError:)`; errors orange, information `notchSurfaceSecondaryText`.
- **L6 (Med). Delete is always on screen, and "Open in Drive" is wrong half the time.** The title row has rename, a folder button labelled "Open in Drive" (the output folder defaults to Documents if there is no Drive), and a "Delete" pill. Fix: rename and an overflow menu (`DroppyCircleButtonStyle(size: 24)`) with "Show in Finder", "Regenerate notes...", "Delete" (`role: .destructive`; confirm per D3). The accessibility label becomes "Show in Finder".
- **L7 (Low-Med). Selected tab.** Selected is Accent, others Quiet, which in the harness are indistinguishable (see "Not seen"). Check once in a real Droppy; if the selected tab is too quiet, tint it explicitly (`DroppyAccentButtonStyle(color:)` takes a colour).
- **L8 (Low). Transcript.** Group headers are all secondary. Make "Me" use the accent (the data is `kind == "me"`), keep others secondary, add "Copy transcript" to the overflow menu.
- **L9 (Low). Empty states are plain secondary text.** "No meetings yet. Record one from the shelf, or import a recording." Add a quiet "Import recording..." button under it. First run is where users learn the widget exists.
- **L10 (Low). Swaps in the surface.** List to detail, the answer card and banners appear instantly; use `DroppyTransition.element` for the answer card and banner, `DroppyTransition.expandedContent` for list to detail. No animation on tab changes.
- **L11 (Low). Hardcoded `Color.orange`, `Color.red`, `Color.blue` for state.** There is no warning or destructive token in `AdaptiveColors`, so this is acceptable, but keep it to those three and put them behind one file-private constant so a future token swap is one edit.

### Notes window (NotesPanel.swift, NotesEditor.swift; code-read only)

- **N1 (High). The window is unverified visually.** The harness cannot show an `NSPanel`. Open risks I cannot rule out from the code: the 12pt header row against the transparent title bar and traffic lights (`fullSizeContentView` with `.padding(DroppySpacing.md)`), and whether `DroppyPanelSurface(cornerRadius: 0)` behind a rounded window matches the host's launcher surface at the corners. Fix: before more work on the window, render `NotesPanelView` into a bitmap (`NSHostingView` plus `bitmapImageRepForCachingDisplay`) from a harness-only demo (`EAVESDROPPY_HARNESS_DEMO=notes`), or take one screenshot from a Playground run, and look at it. - **N2 (High). Warnings and Stop live where the user is not looking.** During a call the user's eyes are on the meeting and this window. The audio warning exists only in the shelf (closed during a call) and an 8 s HUD; Stop exists only in the shelf and the menu bar. Fix: a one-line warning row at the top of the window while `droplet.warnings` is non-empty (same text and action as S3), and a "Stop" button (accent, red, `.small`) at the header's trailing end; "Discard" stays in the shelf and menu. - **N3 (Med). Title bar and header repeat each other.** The title bar reads "Meeting notes — Weekly sync" (truncates in a 300pt window) while the header repeats a record glyph and clock. Fix: window title is the meeting title only; header is the clock and the template control.

(Granola picks a template with `/` in the note; a typed `/` shortcut would need editor support and is not proposed.)
- **N5 (Med). Default position.** Top right, 16pt in, is where Zoom's gallery and participants, Meet's side panel and menu bar popovers live. A remembered frame is already restored. For the first run, prefer the bottom right (above the Dock) or the side opposite the call window; decision D9 (taste, low risk).
- **N6 (Low). Opening with the shortcut.** `show(title:focus:)` is called from the `⌥⌘N` shortcut; keyboard-initiated, repeated actions get no animation. Set `p.animationBehavior = .none` on the panel (my reading of the macOS default is that it fades; not verified here).
- **N7 (Low). Notes are not time-tagged.** Granola's "every bullet links to its transcript timestamp" (v1-scope item 8) needs the editor to record when a line was typed. `DroppyMarkdownEditor` exposes only the text binding; this is a pipeline-side idea (infer by file mtime of the debounced writes) and is out of scope for this UI pass.

## (b) Icon concept (for the merge request's "Icon concept" section)

I have not created, drawn or edited any icon file. `Eavesdroppy.icon` and `icon` in `droplet.json` are untouched. This is text for Jordy:

> **Icon concept.** A single soft droplet (Droppy's own shape) in the Store's glass material, with a short row of five vertical waveform bars inside it, tallest in the middle: a droplet that listens. The bars are the only coloured layer (a warm recording red-orange) so the icon survives the tinted and clear appearances as one tint-able layer over a neutral drop, and still reads at 16pt.
>
> **SF Symbol starting point.** `waveform` (what the droplet's own UI uses today) inside `drop.fill`; alternates if a drop feels too close to Droppy's own mark: `ear.fill` with sound ripples, or `waveform.badge.mic`. Not `record.circle`, which is the live activity's glyph and means "recording now", not the droplet itself.
>
> **Reference description.** A drop outline, point up, a third taller than it is wide; five rounded bars, centred, evenly spaced, the middle one about three times the height of the outer two; one subtle specular edge on the drop and nothing else.

## (c) Findings from the notetaker research that change a recommendation

Primary research: `research/commercial-notetakers.md` (not repeated). A second pass on UI specifics (Granola, Jamie, Krisp, Otter, Fathom, MacWhisper, Notion, Apple Notes; vendor pages fetched this session; thin where marked) changed the following.

1. **Speaker naming: play a clip first (changes L3).** Jamie asks the user to play a short clip per speaker, then type a name or pick from recent contacts; it remembers voices and auto-names later (https://docs.meetjamie.ai/getting-started/identify-speaker.md). Wispr Notetaker and Otter apply a name to every line of that voice (third-party: https://wisprflow.ai/notetaker/ai-notetaker-for-mac, https://www.enterprisetimes.co.uk/2025/06/13/how-to-tag-new-voices-in-otter-ai/). Granola, our reference product, only names speakers in Meet, Zoom and Teams (https://docs.granola.ai/help-center/taking-notes/speaker-attribution.md). So the "play" button per speaker row is added to L3 and promoted, and our rename already applies to a person across meetings.
2. **A Stop pill on the notch is not available, so the notes window carries Stop (changes N2).** Jamie's widget has Stop and expands on click (https://docs.meetjamie.ai/getting-started/recorder.md); Granola has a floating indicator and a stop control at the bottom of the screen (https://docs.granola.ai/help-center/taking-notes/transcription.md); MacWhisper puts Stop bottom right (https://docs.macwhisper.com/article/30-record-meetings); Apple Notes has Done (https://support.apple.com/guide/notes/apdb5106e334). Droppy's rule keeps Stop out of a live activity (hover opens the shelf), so the floating notes window is our equivalent of the draggable widget and must carry the stop control.
3. **The timer next to the menu bar icon is not possible (changes M1).** Jamie shows elapsed time beside its icon (https://docs.meetjamie.ai/getting-started/menu-bar.md); `MenuBarExtraDescriptor` has no label text. The status line goes inside the menu instead, and the live activity already carries the timer.
4. **Call-detected prompt should adopt the calendar event (changes H6).** Granola's ad-hoc prompt names the kind ("Huddle detected", "Call detected", "Meeting detected"), has a single "Take Notes" action, and takes the event's name if the call starts within 15 minutes of a scheduled event (https://docs.granola.ai/help-center/taking-notes/notifications.md). MacWhisper's "Meeting Detected" disappears after 10 s and never auto-records (https://docs.macwhisper.com/article/30-record-meetings). Our 45 s card and the generic "Zoom call" title are the weak points; both change.
5. **Processing should show named steps (changes S7 and LA3).** Jamie shows live steps (Transcribing, Speaker Matching, Writing Summary, Creating Tasks) and a ready notification (https://docs.meetjamie.ai/getting-started/summary.md, https://docs.meetjamie.ai/getting-started/notifications.md); Granola notifies when notes are ready (https://docs.granola.ai/help-center/troubleshooting/notes-not-generating.md). Our pipeline already marks its stages (`Port/Processor.swift`), so the cost is plumbing one string.
6. **Raw versus enhanced notes: two sources of mine disagree.** `commercial-notetakers.md` (2026-10-11) says Granola lets you toggle Raw and Enhanced tabs; the second pass read https://docs.granola.ai/help-center/taking-notes/ai-enhanced-notes.md and found no toggle, only raw text shown in black among the enhanced lines, and a magnifier on each line linking to its source. I did not resolve this. L1 (show "My notes") is kept because our typed notes are otherwise invisible; if Granola's design is "inline, distinguished by colour", that is an alternative to the two-option row, at a higher cost (the pipeline would have to mark which bullets came from user notes).
7. **Library presentation: no evidence, so do not claim any.** No vendor documents row contents, date grouping, full-text search UX or empty states (Granola: "Your notes" list with folders and a People list, https://docs.granola.ai/help-center/getting-started/granola-101.md; Jamie: tag filters with search inside the active tag, https://docs.meetjamie.ai/getting-started/tags.md). L4's grouping and L9's empty state are my design judgement, labelled as such; a People view and tag filters are roadmap candidates, not part of this pass.
8. **Consent reminder is common practice (supports H5).** Krisp shows a start-of-meeting reminder to tell participants (https://krisp.launchnotes.io/announcements/ann_309kpqWGMSrIu); Granola and Jamie offer chat or email notices and a "Transcribing" watermark (https://docs.granola.ai/help-center/consent-security-privacy/transparency-solutions/for-individuals/watermark.md, https://docs.meetjamie.ai/getting-started/recording-consent.md). The reminder stays default-on; only its wording changes.
9. **Not adopted, on purpose.** A "stop under 5 minutes, are you sure?" warning (Jamie): a short accidental recording is cheap to discard here and the confirm would interrupt the discard flow. Pause: none of Granola, Jamie or Krisp documents one in the widget (Krisp's Meeting Companion has it, confirmed only through search summaries). Live transcript bubbles: roadmap, not v1.

Gaps: Otter's and Krisp's help centres returned 403 or were not reached; Fathom's paused state was not re-verified; Superwhisper and Shadow have no usable UI docs; Granola's changelog fetch returned almost nothing, so newer UI changes may be missing.

## Decisions for the user

- **D1.** Should the notes window carry a Stop button, and should the menu bar show a "Weekly sync · 12:34" line? Both contradict "menu bar = buttons only" as planned. I recommend yes to both (N2, M1).
- **D2.** Ask docked at the bottom with Search on top (my recommendation) versus one combined field (L2).
- **D3.** Raise `kit.minAPI` from 1.18.0 to 1.19.0 to use `DropletConfirmationDialog` for Discard and Delete (S5, L6). It removes the two timer-armed confirm states, but older Droppy hosts that lack 1.19.0 would refuse the droplet, and the harness cannot authorize it.
- **D4.** Hold a live-activity seat while notes are being written (LA3)? It adds a visible notch state for minutes after every call.
- **D5.** Keep the menu bar item permanent, or show it only while recording (M4)? Needs a test in Droppy; I did not verify the host re-reads `makeMenuBarExtra` on droplet-driven changes.
- **D6.** Notes window opens automatically: default on (as now) or off (ST3)?
- **D7.** Rename "Stop & save" to "Stop" everywhere (C2)?
- **D8.** Screen-recording warning button: declare `screen-capture` (the user sees the capability) and call `openSystemSettings(for: .screenCapture)`, or open the settings URL through `host.workspace.open` (no capability, unverified)? I did not test either (S3).
- **D9.** Default notes-window position: bottom right instead of top right (N5).
